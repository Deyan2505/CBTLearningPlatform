# 20 — Technology Decision

**Статус: `OWNER APPROVED — .NET 10 LTS`** (ADR-007, Owner Approval Gate, 2026-07-30)

Разширява ADR-001 (`03_DECISION_LOG.md`) в пълен PRD формат за Фаза 0E. **Одобрено от собственика с версийна корекция:** платформата се изгражда на **.NET 10 LTS**, не .NET 8/9 както в оригиналната препоръка по-долу — текстът на сравнението и аргументацията остава валиден концептуално (Blazor Web App си остава правилният избор), само конкретната .NET версия е коригирана навсякъде по-долу. Виж ADR-007 за пълния контекст на одобрението, включително и новата, изрична **Blazor rendering стратегия** (Static SSR по подразбиране, Interactive **WebAssembly** — не Server — само за упражнението, поради privacy изискването потребителското съдържание да не напуска браузъра).

## Сравнение

| Критерий | ASP.NET Core MVC | **Blazor Web App** | React + TS + ASP.NET Core API |
|---|---|---|---|
| Работа във Visual Studio | Отлична | Отлична, единен проект | Добра, два проекта/два дебъгера |
| Сложност за начинаещ/средно напреднал | Средна (изисква JS за интерактивност) | Ниска (само C#) | Висока (C# + TS + SPA концепции) |
| Скорост на разработка | Средна | Висока за интерактивни форми/упражнения | Средна, повече boilerplate |
| SEO | Силно (SSR) | Силно (SSR по подразбиране) | Слабо без мета-фреймуърк |
| Достъпност | Пълен контрол | Пълен контрол | Пълен контрол, повече места за грешка |
| Интерактивност (упражнения) | Изисква ръчен JS | Нативна (C# компоненти) | Нативна, но втори стек |
| Тестируемост | Добра (xUnit) | Добра (xUnit + bUnit за компоненти) | Добра, но два test runner-а |
| Сигурност | Стандартна ASP.NET | Стандартна ASP.NET | Изисква ръчна CORS/token конфигурация |
| Deployment | Просто, 1 артефакт | Просто, 1 артефакт | По-сложно, 2 артефакта или комбиниран host |
| Разходи | Без задължителни платени услуги | Без задължителни платени услуги | Без задължителни, но повече инфраструктура |
| Поддръжка | Добра | Добра | Изисква поддръжка на два екосистема |
| Бъдещо мобилно приложение | Уеб само | Уеб + MAUI Blazor Hybrid преизползва компоненти | Уеб + React Native частично преизползване |
| Административен панел | Directна (Razor+EF) | Директна (Blazor+EF) | Изисква отделен admin UI |
| Управление на съдържание | Директно | Директно | Директно, но допълнителен API слой |
| Мащабируемост | Проста, stateless | Предимно stateless (static SSR); interactive islands ползват SignalR circuit | Stateless API, конвенционално мащабируем |
| Постепенно развитие | Добро | Отлично (render modes: static→interactive per component) | Добро, но по-скъпо на всяка стъпка |
| Преизползване на прототипа | Не (различен език/framework от React прототипа) | Не (различен език — React/JSX не мигрира) | Частично (същия React модел, но различна архитектура: SPA+API вместо CDN-single-file) |

**Забележка за реда "Преизползване на прототипа":** дори React+TS вариантът не позволява буквално пренасяне на кода от `code_artifact.html` (единичен CDN файл без build стъпка, без TypeScript, без разделени компоненти) — виж пълния технически одит в `16_PROTOTYPE_TECHNICAL_AUDIT.md`. Само данните/съдържанието се пренасят, независимо от избрания стек.

## Препоръка

**Blazor Web App на .NET 10 LTS**, потвърждавайки ADR-001 и ADR-007. Няма нова информация от Source Audit-а, която променя тази препоръка — прегледът на SRC-041 засегна съдържанието, не технологията. Версията беше коригирана от .NET 8/9 на .NET 10 LTS при собственическото одобрение (ADR-007) — .NET 10 е текущият LTS release към момента на одобрението.

## Аргументация по слоеве

- **Frontend:** Blazor Web App компоненти на .NET 10 LTS. Render mode: **Static SSR по подразбиране** за всички информационни/образователни страници (начало, уроци, речник, ресурси, FAQ, legal/privacy). **Interactive WebAssembly** (не Server) само за компонентите, обработващи лично съдържание на потребителя — CBT упражнението и локалното проследяване на прогреса — за да остане това съдържание изцяло в браузъра (ADR-007, критично privacy изискване).
- **Backend:** ASP.NET Core (вграден в Blazor Web App хоста), минимална бизнес логика в MVP (зареждане на съдържание от файлове, обработка на упражнението).
- **Database:** **Няма в MVP** (ADR-003) — съдържанието е Markdown/JSON във версиониран Git репозиторий; прогресът е browser local storage, не сървърен.
- **Content storage:** Markdown за уроци (текст + метаданни отпред), JSON за структурирани данни (списък изкривявания, речник) — директно съответства на данните, вече извлечени от прототипа.
- **Testing tools:** xUnit за бизнес логика; bUnit за Blazor компоненти; Playwright за E2E критични потоци (Фаза 4+, когато има реален UI за тестване).
- **Styling approach:** CSS с utility-подобен слой (напр. вграден CSS isolation на Blazor + минимален custom CSS), **не** Tailwind CDN (несъвместимо с production, вижте `16_PROTOTYPE_TECHNICAL_AUDIT.md` т.2) — препоръка за компилиран CSS подход, решение за точния инструмент (напр. Tailwind чрез build stepstep срещу чист CSS) се отлага за Фаза 2 дизайн система.
- **Deployment:** Azure App Service (basic/free tier) или сравним хостинг — детайлен план в бъдеща Фаза 8.
- **Analytics:** без трета страна анализ по подразбиране; ако бъде въведен, privacy-friendly вариант, документирано решение в `03_DECISION_LOG.md` (виж `08_DATA_PRIVACY_SECURITY.md`).
- **Error monitoring:** решава се в Фаза 8 (deployment); не блокира MVP разработката.
- **Authentication:** **Не се въвежда в MVP** (ADR-002). Ако бъде добавена в бъдеще — ASP.NET Core Identity (нативна за Blazor Web App).
- **Локално съхранение на прогреса:** **IndexedDB** препоръчан пред `localStorage` за по-структурирани данни (напр. упражнението), ако е реално необходимо (ADR-007); `localStorage` остава само за малки, нечувствителни настройки/идентификатори (напр. кой урок е "последен посетен"). Достъп през Blazor WebAssembly JS interop, с ясен UI индикатор какво точно се пази.

## Зависимост от одобрение

**Одобрено от собственика (ADR-007, 2026-07-30), с версийна корекция на .NET 10 LTS и добавена изрична rendering стратегия.** Технически изпълними стъпки (Фаза 1) остават блокирани не от липса на одобрение, а от липсваща development среда — виж `02_CURRENT_STATUS.md` и Сесия 4 в `10_SESSION_LOG.md`.
